本週工作週報：DEO IP 遊戲從 Godot 攤位轉戰原生 Web，判官評測體系同步落地

日期：2026-08-28

一、本週整體進展
1. 主導完成 `web_game/` 從零到一開發，不經 Godot export、以 PixiJS + ES modules 零 build 原生重寫遊戲主體，1:1 移植棋盤、消除、特效與音效邏輯，直接讀既有關卡 JSON，顯著提升素材迭代與跨平台展示的效率
2. 獨立完成攤位 demo 換裝，將 `godot_demo` 素材整批置換為 deo_cat_ip 生成包並重新 export，同步移除 BGM 僅保留合成音效，降低授權風險與體積負擔
3. 本週持續產出兩批新 IP 素材（transform soda sprite、whippedbro），美術資產量與主題覆蓋率穩定擴張

二、Web 版重寫與素材整合
1. `web_game/` 內建 tween/ticker 例外隔離機制，避免殘留動畫打到已銷毀節點時拖垮整個渲染迴圈，強化執行穩定性
2. 支援 `?theme=` 參數即時切換任一 `generated_art` run，讓同一套引擎可承載多個 IP 主題並快速對外展示
3. 獨立排查並修正兩個關鍵瑕疵：道具旋轉幀圖白底未去背，以及瀏覽器快取造成的素材版本錯亂，皆已補上自動化防呆（去背後處理、素材版本號機制），避免同類問題重複發生

三、評測 / 品質 / 自動化
1. 獨立設計並實作 `selfcheck.mjs`，針對 match finder 核心邏輯提供 8 項純邏輯自檢，可直接在 node 環境執行，不依賴瀏覽器
2. 修正論文評測管線既有基準誤用問題（原先誤將生成圖當人工基準），並新增 ClaudeJudge 與盤面解析評測腳本，交叉比對多家判官與客觀訊號，讓素材品質的可信度有可量化依據
3. 完成一輪 repo 體檢，清查並清除已 gitignore 卻仍殘留追蹤的舊素材，同步盤點重複的論文備份目錄，降低倉庫維護成本

四、與 AI 協作解決的關鍵挑戰
1. 針對「主題切換後道具動畫退回預設素材」的詭異現象，與 agent 共同定位出根因是 URL 缺少 `theme` 參數而非程式邏輯壞掉，避免了一次誤判方向的除錯
2. 針對生成幀圖去背後瀏覽器仍顯示白底的問題，與 agent 一起釐清是快取而非去背失敗，並直接建立版本號機制讓此類問題日後可自動避免

五、下週重點與展望
1. 延續 deo ip 素材產線的節奏，規劃下一批主題資產生成與換裝驗證
2. 推動 web 版與攤位 demo 的並行維護機制成熟化，讓兩端可同步吃到最新素材而不互相拖累
3. 目標讓 deo ip game 具備可持續擴充主題的素材與評測基礎設施，支撑後續多主題快速上線
